| 28 | The client's transport is **written out** — `CONNECT`, TLS, and a small HTTP/1.1 exchange — rather than delegated to an HTTP crate | The session's egress proxy authenticates `Proxy-Authorization: Bearer <token>`, and the URL it injects is `http://agent:<token>@127.0.0.1:<port>`. | 33 | Secrets read from the environment are **wrapped** so they cannot be printed and are wiped when they drop (`secrecy` / `zeroize`) | The agent reads its provider key from its own environment and its proxy token from the injected `HTTP_PROXY` URL, and both started as ordinary `String`s: a key in a struct field is a key somebody prints, and a freed heap block keeps its bytes until something reuses them. | 34 | The coding belt's **mode is switchable while the session runs**, and `--mode` sets the mode it starts in | The operator understands the mode as session state, so it lives in one cell inside the belt and every reader derives from it: the tool schemas, the arm gate, and the system prompt. | 35 | One `Coding` type with a private exhaustive `Spec` enum, not a module per tool and not a `dyn Tool` registry | Three designs were sketched and scored on interface depth, mode correctness, patch soundness, bounds, extensibility, and diff size. | 36 | The unified diff is **applied in process by `diffy`**, with no `git` and no repository | The operator's correction: shelling out to `git apply` made the tool usable only in a git checkout, which a session's workspace need not be. `gitpatch` parses a unified diff and has no apply function (its public API is `Patch`, `File`, `Hunk`, `Line`, `ParseError`), so `diffy` is the applier: `PatchSet::parse(.., ParseOptions::unidiff())` accepted every shape probed here (git-style, plain `diff -u`, unprefixed nested, creation, deletion, multi-file) and `apply` refuses a hunk whose context does not match. The hunk counts and the diff's skeleton are this crate's, per row 42, because `diffy` treats a declared count as the hunk's extent. Path safety stays the belt's rule, since `diffy` never resolves a path, and the `-p` level becomes a per-path decision because no argv carries one | `agentd/src/patch.rs`; `agentd/Cargo.toml`; the probe file `agentd/tests/scratch_diffy.rs`, deleted before the commit | done |

| 38 | `code_search` is a literal substring search, and `read` is a line window | There is no regex crate in the workspace and a hand-written engine is a bug farm, so the schema says literal and the model narrows and calls again. `read` pages with `start_line` and `line_count` because patching a file does not need the whole of it, and a whole-file read is what the OOM rule forbids. | 39 | No `git` program is named or spawned, so `patch` takes no `--git` and needs no `PATH` | The applier is a library call, so the flag, the `PATH` scan, and the startup warning all go. | 40 | `patch` builds a **complete plan before it writes anything** | A patch that fails on its third file must not leave the first two changed, which a per-file write cannot avoid. `build` parses, resolves every path, reads every base under its cap, and applies every hunk into a `Plan`; only a complete plan is committed. The residual is an operating-system error during the commit, which can leave a prefix written and is reported rather than rolled back, the same way `git apply` behaves on an I/O error | `agentd/src/patch.rs` | done |
| 41 | The mode action is `{"action": "mode"}`: a query with no detail, a switch with `{"mode": <name>}`, and never a tool | A client needs to read the mode as well as set it, and a repeated switch is not an error, so one action answers both with `{"mode", "changed"}`. The switch rides the durable command log, so a restart replays it and converges | `agentd/src/coding.rs`; `agentd/bins/agent-agent.rs`; `agentd/tests/agent.rs` | done |
| 42 | Every hunk's counts are **recounted from its own body**, and the diff's skeleton is checked here rather than trusted to `diffy` | A model cannot count hunk lines, and a probe on this host showed what `diffy` does with that: `@@ -1 +1 @@` in front of a four-line body parses successfully, the first line satisfies the counts, and the rest is tolerated as junk, so the patch applies a no-op and reports success. A blank line where a context line belongs, and a body line after a section, parse the same way. So the counts are derived from the hunk's contiguous body, as `git apply --recount` does, and a `--- ` header with no `+++ ` line or a body line with no header before it is refused, which is what makes a mistyped diff fail loudly instead of half-applying. The two start numbers stay as written, because `diffy` finds a hunk by its context | `agentd/src/patch.rs`; the probe file, since deleted | done |
